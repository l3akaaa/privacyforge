# PrivacyForge

A privacy-first, **local-by-default** data de-identification platform. Upload a
dataset, detect likely sensitive information with multiple complementary methods,
transform it under an explicit policy you control, then verify the result with an
independent second scan before you export.

> **Honesty first.** PrivacyForge does **not** guarantee perfect de-identification,
> does **not** certify legal compliance (FERPA/HIPAA/GDPR), and treats reversible
> tokenization as **pseudonymization, not anonymization**. It never produces a
> file labeled "100% safe". See [`docs/SECURITY-LIMITATIONS.md`](docs/SECURITY-LIMITATIONS.md).

## What works today (Phase 1 MVP)

Implemented and tested (43 passing tests):
- **Ingestion**: TXT, CSV, JSON, XLSX with content-type validation, size limits,
  decompression-bomb guards, and safe value-only XLSX handling (formulas/hidden
  sheets/macros are never silently processed).
- **Multi-layer detection**:
  - Layer A deterministic (regex + validators: Luhn for cards, SSN rules).
  - Layer B NLP (Presidio + spaCy) — **optional**, auto-detected if installed.
  - Layer C dataset-aware (column names, cardinality, format/prefix shapes).
  - Layer D contextual classification (PII / sensitive / quasi-identifier).
  - Layer E custom no-code rules (regex / column name / keyword) with a dry-run.
  - Layer F aggregation (overlap merge, source tracking, review flags).
- **Policy + transform**: redact, mask, tokenize, synthetic (Faker), generalize,
  retain. Five presets, each labeled as a starting point, not a certification.
- **Secure token vault**: AES-GCM authenticated encryption, per-project keys via
  HKDF from an env master key (no hardcoded keys), `secrets`-based tokens,
  HMAC-keyed lookups, authorized-only detokenization, project isolation.
- **Verification**: residual-PII rescan, k-anonymity/uniqueness, data-leakage
  checks, transparent risk report, **fail-safe export gate**.
- **Utility report**: before/after row/column counts, missing values, numeric
  summaries, changed fields.
- **FastAPI** backend with versioned, typed endpoints.

Partial / planned: the Next.js frontend is **implemented** (7 pages wired to the
API); the NLP layer ships as an optional install. See [`docs/ROADMAP.md`](docs/ROADMAP.md)
and the specs in `.kiro/specs/privacyforge-mvp/`.

## Run the web app (frontend)

The backend must be running first (see above). Then:

```bash
cd frontend
npm install
npm run dev           # http://localhost:3000
```

The frontend calls the backend at `http://127.0.0.1:8000/api/v1` by default
(override with `NEXT_PUBLIC_API_BASE`). Walk the seven steps in the top nav:
Dashboard → Upload → Detection Review → Policy Editor → Before/After →
Verification → Export. All results come from the real backend — no mock data.

## Quick start (backend)

```bash
cd backend
python -m venv .venv
# Windows: .venv\Scripts\activate   |   macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt -r requirements-dev.txt

# REQUIRED: set a vault master key (never commit this). Any strong secret works.
# Windows PowerShell:  $env:PRIVACYFORGE_MASTER_KEY = "<a-long-random-secret>"
# macOS/Linux:         export PRIVACYFORGE_MASTER_KEY="<a-long-random-secret>"

pytest -q                     # run the test suite (43 tests)
python -m privacyforge.benchmark   # run the detection benchmark

uvicorn privacyforge.api:app --reload --host 127.0.0.1 --port 8000
# OpenAPI docs at http://127.0.0.1:8000/docs
```

### Optional NLP layer (names, orgs, locations)

```bash
pip install -r requirements-nlp.txt
python -m spacy download en_core_web_lg
```
When installed, the pipeline auto-enables Presidio + spaCy. When not, the
deterministic / dataset-aware / custom layers still run and the API reports
`nlp_available: false`.
